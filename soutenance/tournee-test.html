Banc d'essai · à jouer soi-même

Faire une tournée
de bout en bout

Charger au dépôt, livrer sur site — et observer ce que l'application accepte, ce qu'elle refuse, et pourquoi. Quatre QR codes, une commande pour remettre la tournée à zéro, autant de fois que tu veux.

La règle à vérifier : le type d'étape dicte le mode de scan

ÉtapeCe que tu faisModeTransition
pickup — chargementtu charges le camion au dépôtTransitallocated → in_transit
transit — passagetu constates un point de passagePointageaucune
dropoff — livraisontu décharges et tu installesDéploiementin_transit → deployed

Cette correspondance n'est écrite nulle part dans l'application : ni à l'écran, ni dans le code. C'est aujourd'hui à l'agent de la connaître — c'est la limite que ce banc d'essai met en évidence.

Remettre la tournée à zéro

cd logichain-front/LogiChainMobile/soutenance
./demo-tournee.sh etat        # où en sont les 4 équipements
./demo-tournee.sh prepare     # les remet tous en « Alloué »
Pourquoi deux étapes dans le script : la machine à états interdit deployed → allocated. On repasse donc par le stock (POST /items/:id/return, qui détache l'événement), puis on réalloue le lot en une seule transaction ACID — l'endpoint présenté au MP3. Si un seul des quatre échouait, aucun ne serait alloué.

La procédure

1Remettre à zéro./demo-tournee.sh prepare — les quatre passent en « Alloué ».
2Rafraîchir le téléphoneSynchro → « Retélécharger le secteur ». Sans ça, le cache local garde l'ancien état et tes scans seront refusés pour la mauvaise raison.
3Ouvrir la tournéeTableau de bord → Tournées → RTE-2026-02. Déplie-la : deux étapes, la prochaine est mise en avant. Appuie sur « Tracer sur la carte » pour voir le trajet en pointillés — pointillés parce que la distance est prévisionnelle.
4Étape 1 — le chargement, en mode TransitScanne les quatre QR à la suite. Les quatre doivent être acceptés : allocated → in_transit. Le compteur de session monte à 4, la file d'attente aussi.
5Étape 2 — la livraison, en mode DéploiementRescanne les quatre. Acceptés : in_transit → deployed. La tournée est faite.
6Vérifier côté serveur./demo-tournee.sh etat — les quatre doivent être « Déployé ». S'ils sont encore « Alloué », la synchro n'est pas passée : c'est le décalage entre ton téléphone et le serveur, exactement ce que la file d'attente absorbe.

Les comportements à provoquer

C'est la partie intéressante : chaque refus a une raison différente, et l'application doit la nommer.

Ce que tu faisAttenduPourquoi
Après le chargement, rescanner en Transit ✗ refusé in_transit → in_transit interdit — il est déjà chargé.
Avant le chargement, scanner en Déploiement ✗ refusé allocated → deployed interdit — on ne pose pas sur site ce qui n'a pas voyagé.
Après la livraison, rescanner en Déploiement ✗ refusé deployed → deployed interdit — on ne redéploie pas.
Pointage, à n'importe quel moment ✓ accepté Le constat de présence ne change aucun statut, il n'est jamais refusé.
Viser un QR en continu sans le retirer du champ ✓ un seul scan L'anti-doublon compte 1,5 s depuis la dernière vue du code : il faut qu'il quitte le champ.
Toute la tournée en mode avion ✓ identique Aucune étape du scan ne touche au réseau. La file se vide au retour de la connexion.
En transporteur, l'étape de livraison ✗ verrouillé Le mode Déploiement porte un cadenas : « il achemine, il n'installe pas ». Le chargement, lui, passe.
Le test le plus instructif : fais l'étape 4 en mode avion, puis ouvre le centre de synchronisation avant de rétablir le réseau. Quatre actions t'attendent, dans l'ordre où tu les as faites. Coupe le mode avion : elles partent seules, la file se vide, les statuts se confirment. C'est tout le projet en trente secondes.

Ce que ce banc d'essai met en évidence

L'écran Tournées t'annonce ta prochaine étape et combien d'équipements elle porte — mais pas lesquels, ni dans quel mode les scanner. Pendant ce test, tu dois lire cette fiche pour le savoir. C'est la limite honnête de l'écran dans sa version actuelle : il est informatif, pas encore opérationnel.

Ce qui la comblerait : afficher dans chaque étape la liste des équipements avec leur code QR et leur statut, plus un bandeau « Mode à utiliser : Déploiement » déduit du type d'étape. Les données sont déjà dans le cache local — c'est de la résolution locale, comme le scan.
